

# Aura Pulse90 — Known Limitations

Aura Pulse90 was intentionally built as a fast-moving MVP focused on validating behavioral consistency systems rather than shipping a fully scaled fitness platform.

Current limitations include:

| Limitation | Current Impact |
|---|---|
| No advanced analytics instrumentation | Product decisions still rely partly on qualitative signals |
| Limited AI memory persistence | Coaching context is session-aware, not long-term adaptive |
| Firebase scaling constraints | Architecture is optimized for MVP-stage usage |
| PWA instead of native mobile app | Limited deep device integration |
| No wearable integrations | Recovery tracking depends on manual inputs |
| Limited social/community systems | Product currently prioritizes individual consistency loops |
| Lightweight testing coverage | Core systems are validated primarily through live usage |

These limitations were consciously accepted to prioritize:

- fast iteration velocity
- behavioral validation
- product simplicity
- rapid experimentation
- MVP execution speed

Future roadmap phases are intended to gradually address these gaps without compromising usability or behavioral clarity.
